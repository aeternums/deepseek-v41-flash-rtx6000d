# DeepSeek 16流解码合计2226 tok/s

四张 RTX 6000D 部署 DeepSeek-V4.1-Flash，生产配置保留 **1,048,576 token 上下文和 16 个调度槽位**。单请求的上下文预算包含输入和输出，各请求共享 KV 缓存。配置面向短文本对话、代码生成和逐轮增长的长会话，评估时同时观察解码吞吐和混合负载下的首 token 延迟。

## 推理栈与调度

服务运行在 Local Inference Lab 的 **vLLM** 镜像上，应用 Fraser Price 的 **BRRR** 补丁与 SM120 内核，加载 DeepSeek 官方原版权重。四卡采用 **TP4 张量并行**，**B12X** 提供注意力、MoE、线性层与 PCIe 卡间通信后端。常用批形状通过 CUDA Graph 重放。

解码采用 **DSpark 自适应投机验证**，每步最多提出 7 个草稿 token。长输入分块预填充，单请求每块最多 2,048 token，调度批次预算为 4,096 token。KV 缓存使用 FP8，Engram 小块读走 Linux 页缓存。

## 生产配置基准

| 负载 | 单流 | 8 流合计 | 16 流合计 |
|---|---:|---:|---:|
| 短代码预填充，约 2.15K 输入 token | **5,868 tok/s** | **11,044 tok/s** | **11,172 tok/s** |
| 短代码解码，约 2.15K 输入 token | **548 tok/s** | **1,627 tok/s** | **2,226 tok/s** |
| 普通短对话，端到端 | **246 tok/s** | **842 tok/s** | — |

各并发档来自同一生产配置的独立合成基准。短代码单流取解码速度中位数，并发档取共同解码窗口的最高合计吞吐。短对话从发出请求开始计时，8 流首 token p95 约 **353 ms**。

4 流预填充合计 **9,022 tok/s**。预填充测未命中前缀缓存的请求，每路最多生成 1 token，用输入 token 数除以客户端批次首 token 等待时间，等待时间取批内最慢一路。各并发档取已记录的最好成绩。

长上下文分两种情况测试：

- **前缀缓存已预热**。每个请求有独立的约 10 万 token 前缀，8 流端到端合计约 **750 tok/s**。
- **冷长输入与短请求混合**。单个长请求输入 **1,035,067 token**，首 token 约 **190 秒**，成功找回指定标记并生成 **4,096 token**。在长请求首 token 到达后发出 8 个短请求，均在长请求结束前完成，短请求首 token p95 为 **506 ms**。该延迟对应长请求的生成阶段，冷长输入预填充期间的短请求延迟尚未测量。
